# /handoff-in — 인계 수령 (이어받기)

`/handoff-out` 이 만든 인계서로 작업을 이어받는다. **작업에 착수하지 않는다.** 확인하고 보고하고 대기한다.

모든 출력은 **한국어**로 한다.

---

## 핵심 원칙

> **인계서는 "읽을 것"이 아니라 "실행할 검증 목록"이다.**

인계서에 적힌 사실은 *작성 시점에* 참이었다. 지금도 참인지는 모른다. 그 격차가 이 스킬의 존재 이유다.

⛔ **"확인했습니다"라고 말하기 전에 실제로 도구를 실행한다.** 파일은 Read 로 열고, 상태는 Bash 로 조회한다. 인계서 문장을 근거로 재진술하는 것은 확인이 아니다.

### 정보 출처 우선순위 (충돌 시)

| 대상 | 신뢰 원천 |
|---|---|
| 의도·결정·제약·기각·실패 | **인계서** (다른 데 없다) |
| 현재 상태 (PR·브랜치·파일·배포·DB) | **실측** (인계서보다 우선) |
| compact 자동 요약 | **배경 참고만.** 의도의 근거로 쓰지 마라 |

셋을 뭉뚱그리지 마라. 자동 요약은 "왜"에 대해 손실이 크다.

---

## Step 0: 인계서 확보

- 인자로 경로가 오면 Read
- 없으면 사용자가 붙여넣은 코드블럭을 사용
- 둘 다 없으면 **여기서 멈추고 요청**한다. 추측으로 시작하지 마라

## Step 1: 참조 대상 전수 추출

인계서에서 아래를 **빠짐없이** 목록화한다. 이후 단계는 이 목록을 소진하는 것이다.

- vault 문서 경로
- 코드 경로 (`file:line`)
- 브랜치·커밋 해시
- PR 번호·URL
- 실행 명령어와 기대값
- DB/인프라 식별자 (테이블·터널 포트·시크릿 키명)

목록 개수를 밝힌다. 예: `문서 4 · 코드 11 · 브랜치 2 · PR 2 · 명령어 6`

## Step 2: 검증 실행 — 휘발성 순서

`[시간]` → `[일]` → `[상시]` 순으로 확인한다. 낡을 확률이 높은 것부터다.

### `[시간]` 먼저 (가장 자주 틀린다)

```bash
gh pr view <N> --json number,state,baseRefName,headRefName,mergedAt
git -C <repo> rev-parse --abbrev-ref HEAD && git -C <repo> log --oneline -3
git -C <repo> status --porcelain
git -C <repo> rev-list --left-right --count origin/<base>...HEAD
```

### `[일]` — 코드·문서 실재 확인

- 인계서가 지목한 `file:line` 을 **실제로 Read** 해서 그 내용이 맞는지 본다
- 라인이 밀렸으면 밀렸다고 보고한다
- 인계서가 "유일한 지점"이라고 주장하면 **grep 으로 직접 재확인**한다. 소비처 주장은 자주 불완전하다

### `[상시]` — 결정·제약

읽고 준수 대상으로 등록한다. 검증 대상이 아니다.

⛔ 인계서에 태그가 없으면 스스로 분류해서 같은 순서로 진행한다.

## Step 3: 불일치 보고 (⛔ 가장 중요한 산출물)

인계서와 실제가 다른 항목을 **근거와 함께** 먼저 보고한다. 조용히 덮어쓰지 마라.

```
⛔ 인계서와 다른 사실 N건
  · PR #23  인계서 "리뷰 대기" → 실제 MERGED (2026-07-31T08:06:47Z, main 4c2dbd1)
  · <경로>  인계서 :34 → 실제 :41 (라인 밀림, 내용 동일)
```

불일치가 0건이어도 **"0건 확인"이라고 명시**한다. 침묵은 확인과 구분되지 않는다.

## Step 4: 미확인 항목 명시

확인하지 못한 것은 **"미확인"으로 남긴다.** 추측으로 메우지 마라.

- 접근 불가(터널 미연결·권한 없음·서버 미기동)
- 인계서에 경로가 없어 못 찾은 것
- 사용자만 알 수 있는 것 (외부 담당자 답변, 배포 승인 여부 등)

각 항목에 **무엇이 있으면 확인 가능한지** 한 줄 덧붙인다.

## Step 5: 대기 상태 확인 후 정지

마지막에 아래를 보고하고 **멈춘다.**

```
현재 대기 상태 : <인계서 §0 + 실측으로 확정한 것>
다음 행동 후보 : <1~3개, 각각 한 줄>
내가 기다리는 것: <사용자의 어떤 요청·결정·입력인지>
```

⛔ **여기서 코드를 고치거나 명령을 실행하지 마라.** 사용자가 지시할 때까지 대기한다.
사용자가 §0 과 다른 걸 시키면 그쪽이 우선이다.

## 완료 조건

- [ ] Step 1 목록 개수를 밝혔다
- [ ] `[시간]` 항목을 **실제 명령 실행**으로 확인했다 (인계서 재진술 아님)
- [ ] 인계서가 "유일한 지점"이라 한 주장을 직접 grep 으로 재확인했다
- [ ] 불일치를 근거(해시·타임스탬프·라인)와 함께 보고했다. 0건이면 0건이라고 말했다
- [ ] 미확인 항목을 미확인이라고 명시했다
- [ ] 대기 상태를 보고하고 **착수하지 않고 멈췄다**
