# /handoff-out — 인계서 생성 (세션 넘기기)

세션이 거의 찼거나 종료·compact 직전에 실행한다. 출력물은 **다음 세션의 user turn 에 그대로 붙여넣을 코드블럭**이다.

모든 출력은 **한국어**로 한다.

---

## 핵심 원칙 (이것만 지키면 나머지는 형식이다)

> **재도출 가능한 것은 명령어로, 재도출 불가능한 것은 본문으로.**

세션 간 기억은 없다. 새 세션은 재구성할 뿐이다. 그래서 목표는 *기억을 흉내내는 것*이 아니라 **싸게 재관찰하게 만드는 것**이다. 기억은 낡지만 재관찰은 낡지 않는다.

| 분류 | 예 | 인계 방식 |
|---|---|---|
| **재도출 가능** | PR 상태, 브랜치·커밋, 파일 존재, 빌드·테스트 결과, DB 건수 | ⛔ 결론을 단정하지 마라. **명령어 + 기대값**을 적어 `-in` 이 실행·대조하게 한다 |
| **재도출 불가** | 결정의 이유, 기각한 제안, 실패한 시도, 사용자가 말로 준 제약 | 본문에 그대로. 코드·git 어디에도 없어 **잃으면 영구 소실**이다 |

⛔ **서술체로 쓰지 마라.** 인계서는 다음 세션의 최고 권위 자리(user turn)에 들어간다. 과거 보고서가 아니라 **나에게 내리는 명령문**으로 쓴다.

```
❌  "PR #23 은 리뷰 대기 상태였다"                  → 배경으로 흡수되고 검증 안 됨
✅  "① gh pr view 23 --json state 실행. 기대 OPEN.
     다르면 즉시 보고하고 멈춰라"                    → 실행되고 불일치가 잡힘
```

---

## Step 0: 이번 세션 산출물 목록화

기억이 아니라 **증거**로 만든다.

```bash
git -C <repo> log --oneline <세션시작>..HEAD
git -C <repo> status --porcelain
git -C <repo> diff --stat <세션시작>..HEAD
```

- 다중 레포 작업이면 레포별로 전부
- 코드 외 산출물도 목록에 넣는다: 배포 실행, DB 변경, PR 생성·머지, 라이브 검증, 사용자에게 받은 외부 정보
- **미완·차단된 것**을 빠뜨리지 마라 — 인계에서 가장 값비싼 항목이다

## Step 1: 기록 여부 감사 (⛔ 주장 금지, 검색으로 증명)

Step 0 목록의 각 항목이 **vault 에 실제로 있는지** 검색한다. "기록했습니다"라고 말하지 말고 **hit 수를 제시**한다.

```bash
VAULT=$(dirname $(dirname $(python3 -c "import os;print(os.path.realpath(os.path.expanduser('~/.claude/CLAUDE.md')))")))
grep -ril "<식별 키워드>" "$VAULT/projects/" | head
```

- 식별 키워드 = 함수명·PR 번호·테이블명·에러 문구 등 **고유한 것**
- 결과를 그대로 보고한다: `writeUserSetting 0건, qa6002 0건, PR 9163 0건 → 미기록`
- 0건이면 **안 된 것이다.** 이 단계에서 자신을 봐주지 마라

## Step 2: 누락분 vault 기록

글로벌 `CLAUDE.md` §Vault 도메인 라우팅 규약을 따른다.

1. `ls projects/<repo>/` 로 기존 도메인 확인 → 매칭되면 그 안에, 새 주제면 **사용자에게 1줄 확인 후 대기**
2. 작성 직전 경로 1줄 알림: `→ <path> 에 작성합니다`
3. typed-edge 부착: `domain` / `moc` / `depends-on` / `implements` (관계 이유를 1줄로 못 적으면 엣지를 만들지 마라)
4. 이번 작업이 기존 문서를 대체하면 **구 문서에 `superseded-by`** 를 단다 — 다음 세션이 낡은 절차를 따르는 걸 막는다
5. 상대 날짜 금지. 절대 날짜로 쓴다

## Step 3: 메모리 갱신

- 기존 메모리와 중복되면 **새로 만들지 말고 그 파일을 갱신**한다
- `MEMORY.md` 에 1줄 색인 추가
- 코드·git 이 이미 말해주는 것은 메모리에 넣지 않는다

## Step 4: 인계서 작성

### 분량: 본문 100~160줄

크기가 아니라 **주의 배분**이 병목이다. 상세는 vault 에 있고 인계서는 *색인 + 검증 프로토콜*이다.
⛔ **vault 내용을 인계서에 복제하지 마라.** 복제하면 둘이 어긋나 진실이 두 개가 된다.

### 구조 (순서 고정)

| § | 내용 | 줄수 |
|---|---|---|
| **0** | **지금 대기 상태 + 다음 행동 1개** | ~10 |
| **1** | **검증 체크리스트** — 명령어 + 기대값 + 체크박스 | 15~30 |
| **2** | **재도출 불가 정보** | 30~60 |
| **3** | 문서·코드 색인 (경로만) | 20~40 |
| **4** | 남은 일 (우선순위·차단요인) | 10~20 |

§0 을 맨 앞에 두는 이유: 실제로 할 일이 맨 앞이어야 실행된다. 과거 서사가 앞에 오면 안 된다.

### §1 검증 체크리스트 — 휘발성 태그를 단다

| 태그 | 의미 | 예 |
|---|---|---|
| `[시간]` | 시간 단위로 낡음 | PR 상태, 브랜치 tip, 배포 상태, 실행 중인 프로세스 |
| `[일]` | 일 단위로 낡음 | 코드 경로·라인번호, 파일 존재, 스키마 |
| `[상시]` | 안 낡음 | 결정·근거·제약 |

`-in` 은 `[시간]` 부터 검증한다. 체크리스트는 **열거된 명령어**로 쓴다 — "확인해라"는 안 지켜지고 열거된 목록은 지켜진다.

### §2 재도출 불가 정보 — 4분류

| 분류 | 정의 | 왜 비싼가 |
|---|---|---|
| **결정** | *우리가* 정한 것 + 이유 | 이유 없으면 다음 세션이 재논의한다 |
| **기각** | *외부*(다른 모델·리뷰·사용자)가 제안했고 죽인 것 + 반증 근거 | **또 올라온다.** 기록 없으면 같은 걸 다시 제기받는다 |
| **실패** | 실제로 시도했다 안 된 것 + 실측 증상 | 재시도 비용이 가장 크다 |
| **제약** | 사용자가 말로 준 금지·선호 | 대화에만 존재. 위반하면 신뢰를 잃는다 |

> ⛔ **이 4분류는 스키마가 아니라 회상 프롬프트다. 어디에도 안 맞으면 분류하지 말고 그냥 써라. 분류 판단에 시간 쓰지 마라.**
> 항목을 잃는 것보다 분류가 지저분한 게 훨씬 낫다.

### §3 색인

- 문서: **읽는 순서대로** 나열 (`0. 먼저 읽을 것` 형태)
- 코드: *판단 근거가 된* 경로만 `file:line` 으로. 전체 파일 목록이 아니다
- 각 줄에 **왜 이걸 봐야 하는지** 반 줄

## Step 5: 출력 + 저장

1. **코드블럭으로 출력** — 사용자가 드래그·복사한다
2. **동시에 vault 에 파일로 저장**: `projects/<repo>/handoff/<YYYY-MM-DD>-<slug>.md` (레포 무관 작업이면 `_meta/handoff/`)
   - 클립보드는 유실된다. 파일이 있으면 `/handoff-in <경로>` 로도 진입 가능하고 인계서 자체가 그래프에 들어간다
   - frontmatter + typed-edge 부착
3. 저장 경로를 사용자에게 1줄 알린다

⛔ vault 는 자동 커밋·푸시된다. **직접 `git commit`/`git push` 하지 마라.**
